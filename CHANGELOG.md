# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- Kit tooling: strict TypeScript compiled to `dist/` (built by `prepare`), ESLint with `typescript-eslint` strict and stylistic type-checked rules, Vitest with coverage thresholds of 90% (lines, functions, statements) and 80% (branches).
- `opdk` CLI skeleton: command registry, `--help`, `--version`, `<command> --help`. An unknown command or a failing command exits 1 with a message that names the command and, for an unknown one, points to `opdk --help`; the stack prints only with `OPDK_DEBUG=1`. `bin/opdk.js` is type-checked and prints `✗ opdk: <message>` and exits 1 when the CLI fails to load.
- `opdk.config.mjs` loading with `defineConfig`, unknown top-level keys rejected, and `manifest.json` reading with validation.
- CI on pull requests and pushes to `main` (typecheck, lint, tests, build, pack-and-install smoke), plus a tag check that `vX.Y.Z` matches the `package.json` version.
- `npm run smoke` runs the pack-and-install smoke locally: it builds first, installs the packed tarball into a temp project, calls `npx --no -- opdk` and runs `opdk build` on a tiny fixture plugin.
- Build module: `opdk build` bundles with esbuild for platform `browser` (format `cjs`, the `module.exports` footer, `obsidian`, `electron` and the CodeMirror packages external, minified, target `es2020`), builds CSS, and runs the bundle check. The code comes from Dashy's `build` script and its `assert-bundle.cjs`, `build-css.cjs` and `build-vault.cjs`.
- `opdk assert-bundle [file]` fails when the bundle contains Node-only code (`process`, `node:` imports, `__dirname`, markers of the Node build of `yaml`), the check that would have caught Dashy 1.0.0 on mobile. Skipped for `isDesktopOnly` plugins.
- `opdk build-css` inlines `@import` lines recursively.
- `opdk build --vault [dir] [--watch]` builds an unminified bundle into a dev vault, then rebuilds `styles.css` and copies it and `manifest.json` after every build. `--watch` follows the sources through esbuild and polls (every 300 ms) the CSS entry, every file it imports, and `manifest.json`; imports added or removed while it runs are tracked. `dir` falls back to `VAULT_PLUGIN`. Watch builds once at start, and when a CSS step fails the files it had already read stay polled, so fixing them syncs again; a missing `@import` target is polled too, so creating it syncs. Ctrl+C stops watch cleanly. Editing `opdk.config.mjs` needs a restart of watch.
- `build` section in `opdk.config.mjs`: `entry`, `outfile`, `minify`, `target`, `external`, `loader`, `css`. Defaults match Dashy's release build.
- `esbuild` 0.28.2 as the kit's first runtime dependency, pinned exactly. The plugins already use it, and a plugin installing the kit needs no separate esbuild for `opdk build`.
- `opdk build --vault` logs where the folder came from (`--vault` or `VAULT_PLUGIN`) and refuses, with exit 1 and nothing written, a folder whose `manifest.json` holds another plugin id (`--force` overrides this one), a folder that resolves to the plugin root, a value starting with `~` (nothing expands it) and an empty `--vault ""` / `--vault=`. `--vault=<dir>` is in the usage text, and `--force` is rejected without `--vault`. Dashy's `build-vault.cjs` had no guard, so a `VAULT_PLUGIN` left exported in a shell let one plugin overwrite another in the dev vault.
- Build documentation: Mermaid flowcharts, GIFs recorded with VHS (`npm run docs:media`, needs `vhs` and `ffmpeg`), full options tables and example output in the README.
- Skill `skills/build/SKILL.md`.
- `CommandContext.onInterrupt` (optional) for long-running commands.
- Coloured CLI output through one reporter (`CommandContext.reporter`): `✓` green for a step that passed, `✗` red for one that failed with its hint indented underneath, `·` dim for progress, `!` yellow for a warning. Failures (and esbuild's messages) go to stderr and the `✓ · !` lines to stdout; with `--vault`, `build had N error(s)` therefore moved to stderr. Colour rules: a non-empty `NO_COLOR` turns it off, `FORCE_COLOR` (anything but `0` and `false`) turns it on even on a pipe or with `TERM=dumb`, `TERM=dumb` turns it off, `GITHUB_ACTIONS=true` turns it on, otherwise it needs a terminal. The symbols stay in plain output. The output format is for people and is not a stable interface to parse: use the exit code.
- Scanner module: `opdk scan` runs the community plugin scanner's own ESLint configuration (a mirror of `eslint-plugin-obsidianmd` 0.5.1, `docs/configuration.md`, taken 2026-11-10), a CSS check (`!important`, `:has`, browser features Chrome 142 lacks, through PostCSS and doiuse) and two source checks over the files git tracks. It exits 1 when a step has a finding: the scanner's ESLint warnings count as findings, advisory `!` lines (`ts-suppression`) do not. Only the ESLint configuration is published upstream; the CSS and manifest checks reproduce findings seen on plugin listings. Output is `file:line  rule  message`, grouped by step through the reporter. The code comes from Dashy's `scorecard-check.cjs` and `scanner.eslint.config.mjs`.
- `obsidian-plugin-dev-kit/eslint` exports `obsidianPlugin({ rootDir, tsconfig, ignores })`, the lint config Snipsy, Dashy and Garmy share, built on `eslint-plugin-obsidianmd`'s `recommended` preset, and `DEFAULT_IGNORES`, the 12 paths it leaves out (what all three plugins leave out, the intersection of their lists; a path only some of them have, such as `site/**` or `src/test/**`, goes in that plugin's `ignores` option), so a config can extend or print them.
- `opdk scan` loads ESLint, `eslint-plugin-obsidianmd`, `typescript-eslint` and `doiuse` only when it runs. Every other command and `opdk --help` start as fast as before and never read `manifest.json` through the plugin.
- `opdk scan` skips tracked symlinks and runs git without the `GIT_*` environment variables, so a hook or worktree session cannot point it at another repository.
- `scan` section in `opdk.config.mjs`: `ignore` (globs). Nothing is ignored by default.
- `opdk scan` warns (`!`, the scan still runs) when the `eslint` package that `eslint-plugin-obsidianmd` resolves is another major than the ESLint that runs, naming both versions and the fix (`"overrides": { "eslint": "$eslint" }` in `package.json`, then `npm install`).
- `manifest.json` reading keeps the optional `description`.
- Dependencies, exact-pinned: `eslint-plugin-obsidianmd` 0.5.1, `typescript-eslint` 8.72.2 (was a devDependency), `postcss` 8.5.32, `doiuse` 6.0.6. Peer dependencies: `eslint` (`^9.19.0 || ^10.0.0`, the intersection of obsidianmd's `>=9.19.0` and typescript-eslint's `^8.57 || ^9 || ^10`, within what the plugins run: 9.39 and 10.14) and `typescript` (`>=4.8.4 <6.1.0`, the peer range of typescript-eslint). A test pins the obsidianmd version the mirrored configuration was diffed against, so a bump forces a re-diff.
- Scanner documentation: `docs/scanner.md`, a short README block, GIFs recorded with VHS, skill `skills/scanner/SKILL.md`. `npm run smoke` runs `opdk scan` on the fixture, clean and with a finding.

### Changed

- `engines.node` is `^22.13.0 || >=24` (was `>=22.12`): ESLint 10 and `eslint-plugin-obsidianmd` 0.5.1, which the scan loads, require it. CONTRIBUTING and README say so.

Differences from the scripts the plugins have today, per plugin. Anything not listed behaves as before.

- Dashy (`build`, `assert-bundle.cjs`, `build-css.cjs`, `build-vault.cjs`):
  - A missing `@import` is an error that names the importing file (Dashy printed a warning and left the `@import` in the output), and an import cycle is an error (Dashy overflowed the stack). The warning for `@import` of a URL is gone; URL imports stay in place for the browser.
  - A missing CSS entry makes `opdk build` skip the CSS step and keep `styles.css` (`build-css.cjs` died with ENOENT). `opdk build-css` exits 1 with a message that names the entry.
  - The bundle size line is in kilobytes with one decimal (`0.6 KB`), computed from the byte length; Dashy rounded the UTF-16 string length.
  - `--vault` and `--watch` are flags of `opdk build` instead of separate scripts. A vault build prints `built` first and `assets copied` after it, `--watch` survives an initial compile error and recovers when the file is fixed, and with `build.css: false` it copies a `styles.css` from the plugin root if there is one.
- Snipsy (`build`, `scripts/build-css.cjs`, `scripts/build-vault.cjs`):
  - Its `build-css.cjs` is Dashy's file (only the comments differ), so the CSS differences listed for Dashy apply to Snipsy's `npm run build` too.
  - The old script copied the root `styles.css` as is and watched it and `manifest.json` with `watchFile`. The kit rebuilds `styles.css` from `src/styles` on every sync, so a hand edit to the root `styles.css` during `dev:vault` is overwritten.
  - The release and vault bundles become platform `browser` (the `build` script and `build-vault.cjs` both used `node`). The release `main.js` changes: yaml's browser build replaces its Node build, so smoke-test the migrated Snipsy on a phone. `npm run build` gains the bundle check; today's `main.js` fails it and the kit's build passes it.
- Garmy: `opdk build` gains `--minify` and two `@codemirror` externals (`@codemirror/state`, `@codemirror/view`), and needs `loader: { ".png": "dataurl" }` in `opdk.config.mjs`.
- All plugins: `.css` is a `text` loader by default in release and vault builds. Dashy's and Snipsy's vault builds had it; it changes nothing until a plugin imports a `.css` file, and it prevents "No loader is configured for .css". `build.loader` entries merge over it.
- Scanner, differences from the scripts the plugins have today. Anything not listed behaves as before.
  - All plugins:
    - Dropped because an upstream rule covers them now, checked against 0.5.1 on sample code: `no-bare-document` (`obsidianmd/prefer-active-doc`), `no-bare-timers` and `no-active-window-timer` (`obsidianmd/prefer-window-timers`), `no-create-el-div-span` (`obsidianmd/prefer-create-el`), `settings-tab-missing-get-setting-definitions` (`obsidianmd/settings-tab/prefer-setting-definitions`).
    - Dropped because upstream contradicts it: `no-bare-window` flagged `window.*` (`window.innerWidth`, `window.matchMedia`); `prefer-active-doc` states that `window` is left alone. `activeWindow.requestAnimationFrame` is no longer flagged either, as 0.5.1 does not flag it.
    - The code checks (domain assembly, `@ts-` directives) take `.js`, `.jsx`, `.tsx`, `.cjs`, `.mjs`, `.cts` and `.mts` under `src/` as well as `.ts`. They skip `test/`, `tests/`, `__tests__/`, `__mocks__/` and `node_modules/` folders and `*.test.*` and `*.spec.*` files (the old scripts skipped `test/`, `__mocks__/`, `node_modules/`, `*.test.ts` and `*.spec.ts`). The old scripts walked the disk, untracked files included; the new checks see only the files git tracks.
    - The comment stripper now also applies to the domain-assembly check (a JSDoc example no longer counts), and the check sees single-quoted arrays. `@ts-ignore` and its kin match only as a comment directive, and stay a warning that does not fail.
    - `src/preview/` is no longer skipped by the source checks (the scanner reads it; Dashy's and Garmy's scripts skipped it).
    - The manifest check escapes regular-expression characters in the plugin name correctly (the old escape doubled the backslash).
    - `!important` inside a CSS comment no longer counts (Garmy's and Snipsy's scripts matched it on the raw line).
    - The manifest check tests the name with a lookahead (`(?![A-Za-z0-9_])`) instead of `\b`, so a name that ends in a symbol, such as `Foo+`, is matched.
    - The scan no longer aborts when there are no sources (Dashy's and Garmy's scripts exited 2, Snipsy's failed with `settings-tab-missing-file`). The lint step reports the files it linted, `manifest.json`, `package.json` and `LICENSE` included.
    - `js.configs.recommended` and `tseslint.configs.recommended` are not added by the scan: `obsidianmd`'s preset already carries both. The preset reads ESLint's core rules from the ESLint resolved next to `eslint-plugin-obsidianmd`; where that is a nested ESLint 9 under a root ESLint 10 (Dashy's and Garmy's trees), `preserve-caught-error`, `no-useless-assignment` and `no-unassigned-vars` are missing from it, which Dashy's `js.configs.recommended` block worked around. `opdk scan` warns about the mismatch; `"overrides": { "eslint": "$eslint" }` in `package.json` plus `npm install` fixes it (`npm dedupe` does not: `@microsoft/eslint-plugin-sdl`, `eslint-plugin-import` and `eslint-plugin-react` peer on ESLint 9), or keep a `js.configs.recommended` block.
    - A file no `tsconfig.json` covers is linted without type information by the scan itself, instead of through a "config files without type checking" block in the plugin's ESLint config that lists such files by glob. Such a file that cannot be parsed fails the scan.
  - Dashy (`scorecard-check.cjs`, `scanner.eslint.config.mjs`):
    - No tracked CSS is not an error. Exit code is 1 for any failing finding and the command fails with a message, not exit 2, when git is missing.
    - Output: `file:line  rule  message` grouped by step through the reporter, not `❌ [rule] file:line` blocks. Findings no longer carry an `error:`/`warning:` prefix or a source snippet.
  - Garmy (`scorecard-check.cjs`):
    - The ESLint step is new for Garmy.
    - The CSS check is new in two respects: `:has()` and the doiuse feature checks (features Chrome 142 lacks or supports partly) did not exist there.
    - Its `no-active-window-timer` and `no-bare-timers` tested the whole stripped file instead of a line, so one hit reported every line; covered by `prefer-window-timers` now.
    - The CSS check no longer looks only at `src/styles/`: every tracked `.css` counts, `site/assets/` included, and `!important` fails instead of warning. Add `scan: { ignore: ["site/**"] }` to leave `site/` out on purpose. Run on the committed tree it reports 36 lint findings and 20 CSS findings, all under `site/assets/`.
  - Snipsy (`scorecard-check.cjs`):
    - `!important` goes from a warning to a failing finding, and `settings-tab-missing-file` is dropped (it only guarded the hardcoded `SettingsTab.ts` path).
    - The `mask` check is dropped: doiuse against Chrome 142 reports no CSS mask finding. The `:has()` check now reads CSS with PostCSS (so comments no longer count) and covers every tracked `.css`, not only `src/styles/`; this adds `text-decoration` (partial support) at `src/styles/main.css:1448` and `styles.css:1512`.
    - It hardcoded the plugin name and `src/ui/components/SettingsTab.ts`; both come from the manifest and the ESLint rule now.
    - The ESLint step is new for Snipsy. On the committed tree it reports `integration/run-matrix.ts:1` (`no-nodejs-modules`) and `package.json:57` (`moment`, `depend/ban-dependencies`); on ESLint 10 also `src/packages/text-snippets.ts:187` (`preserve-caught-error`) and `src/ui/components/community/PackageBrowser.ts:522` (`no-useless-assignment`). ESLint 9.39 has both rules too, but only ESLint 10 added them to `recommended`; on 9, enable them yourself.
  - `obsidianPlugin()` against the plugins' own `eslint.config.js`: it does not set `@typescript-eslint/no-require-imports` (Dashy only), `globals.process` (all three; `no-undef` is off for TypeScript in 0.5.x), a `ui/sentence-case` override (off in the 0.5.x preset already) or `@typescript-eslint/no-misused-promises` (replaced by the preset's obsidianmd rule). Snipsy's promotion of every warning to an error is replaced by `eslint --max-warnings=0`. Snipsy's own config scoped the preset to `src/**/*.ts` and filtered the `package.json` block out; `obsidianPlugin()` does neither, so Snipsy's `npm run lint` newly fails on `package.json:57` (`moment`, `depend/ban-dependencies`) and lints `manifest.json` and `LICENSE`. Snipsy's config also kept the preset off `src/test/**`; pass it through `ignores`, or `npm run lint` fails on the test stubs.
